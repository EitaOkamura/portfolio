# 0001: 静的 SPA として S3 + CloudFront で配信する

- 状態: 採用
- 日付: 2026-09-21

## 背景

ポートフォリオを HTML / CSS / jQuery の 1 枚ものから作り直すにあたり、
配信方法を決める必要があった。元の構成は S3 + CloudFront + Route 53。

## 決めたこと

React + Vite で静的ファイルを吐き、S3 に置いて CloudFront から配信する。
サーバサイドレンダリングはしない。

ルーティングは `react-router-dom` のクライアントサイドルーティングで、
CloudFront のカスタムエラーレスポンス（403/404 → `/index.html`、200）で
直リンクを成立させる。

## なぜ

- **費用**: CloudFront は 1TB/月・1000万リクエスト/月まで無期限で無料。
  S3 の保管は数 MB。Lambda@Edge や SSR 基盤を入れると無料枠を出る可能性がある
- **内容が静的**: 経歴とスキルの一覧で、ログインも動的なデータも無い。
  サーバを持つ理由が無い
- **お問い合わせは Google フォームで足りる**。バックエンドを持たずに済む

## 捨てたもの

- **SSR / Next.js**: OGP を動的に出す必要が無く、ページ数も少ない。
  Amplify や Vercel を使えば楽だが、AWS の構成を自分で組むこと自体が
  このポートフォリオの題材でもあるため、S3 + CloudFront を維持した
- **クエリ文字列や Cookie に応じたキャッシュ分岐**: 使っていないので
  `CachingOptimized` をそのまま使う

## 結果として気をつけること

- 403 と 404 の両方を `/index.html` に流すので、**本当に存在しないパスも 200 で返る**。
  画面側で 404 を出す（`src/pages/NotFound.tsx`）
- `assets/` 配下はファイル名にハッシュが付くので長期キャッシュ、
  それ以外は `max-age=0, must-revalidate` にする。デプロイのワークフローで分けてある
